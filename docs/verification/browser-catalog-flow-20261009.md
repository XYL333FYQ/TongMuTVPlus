# 目录接入、选片和房间切集复验

时间：2026-10-09 UTC。本轮仅修改 TongMuTVPlus；相邻 TongMu 和只读 references 未修改。未初始化 Git、提交、推送或部署。

## 验收环境与方法

继续使用 Temp 下的隔离 SQLite 和 WSL Node 预览。通过管理页登录测试站长，在「视频源配置」添加 `qa-original-cms`，地址为 `http://localhost:3202/api.php`。测试服务只监听 loopback，位于系统 Temp，不加入产品源码。标准 CMS 返回原创海报、简介和两集已有原创媒体：第一集 MP4、第二集带 token 的 HLS。

所有网页动作使用内置浏览器的真实表单、海报菜单、观看选择和播放器按钮。DOM/CDP 只读取原生视频、几何位置和网络事件，没有直接操作 React/房间状态容器。产品代码改变后完整刷新两个客户端再做最终切集验收。

这证明本站如何接入指定格式的目录，不证明免费电影网站、TVBox Spider 或任意远端来源稳定可用。来源协议不兼容、签名过期、浏览器解码失败仍需分别处理。

## 确认问题与修复

1. **海报详情丢失来源简介。** 搜索结果有简介，聚合/单源海报却未传给已有 DetailPanel；实际详情显示 TMDB 搜索失败。现在将已有简介和对应集数传入，游客仍使用公开海报通路。完整刷新后的实际窗口显示原创简介、2 集、CMS 来源；没有把外部 TMDB 可用性当作本地简介显示的前提。
2. **滚动后播放器遮挡片单。** 实测 BODY 已滚动 654.667px，播放器占位 top=-391.521px，真实画面却仍在 263.146px。Element scroll 不冒泡，旧监听漏掉 BODY 滚动。改为捕获滚动事件；修复后占位/画面同为-391.521px，原视频 backendNodeId=16664 保持，片单可见可点。回归用例旧代码失败，修复后通过。
3. **片单第 1 集被个人第 2 集记录覆盖。** 实际片单写第 1 集，但聚合播放地址没带集数，主持开始一起看时加载个人第 2 集记录。新片单地址明确集数；已有片单播放时采用其已保存的集数，不重写数据库。播放器初始化以明确地址集数优先，没指定集数的个人观看保留既有续播。集数监听只在地址参数实际变化时更新，主动切集不再被旧地址反复拉回。

原始只读观察与筛选后的事件见 `catalog-browser-20261009.json`；截图为同目录 `catalog-*.jpg`。默认视口随应用窗口改变，已记录实际 615×668 与 1042×871，不把桌面窄窗口当真机。
