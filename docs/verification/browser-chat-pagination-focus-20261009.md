# 聊天历史分页、阅读位置与失焦未读复核

日期：2026-10-09 UTC。继续使用系统Temp下隔离SQLite、qa-owner/qa-member和本地验收房间，不接触正式数据，不发送给真实用户。

本轮没有修改产品源码；通过实际聊天表单生成160条带编号的测试消息，逐条在房主页面确认发送结果，遵循服务端20条/10秒限制。加上已有6条消息、失焦与旧消息阅读各1条，最终168条。

## 实际分页与阅读行为

成员完整刷新后，聊天收起时显示160条未读；实际打开时DOM仅有最近100条，序号67–166。之后另收到失焦检查消息167，因此第一次加载较早记录前共有101条。

| 场景 | 直接证据 |
| --- | --- |
| 第一页较早记录 | 实际向上滚动并点击“查看更早的消息”；Socket请求beforeSeq=67、limit=50，回复序号17–66共50条；DOM从101增至151条，最早17、最新167，唯一数151。原第67条屏幕y=269.333→269.583，约0.25px差异。 |
| 最后一页 | 再次向上滚动并点击；请求beforeSeq=17、limit=50，回复1–16共16条。DOM共167条且全部唯一，历史按钮消失。原第17条屏幕y=269.333→269.625，约0.292px差异；不会跳到最早或最新消息。 |
| 阅读旧消息时收到新消息 | 停在第17条附近，房主通过表单发送消息168。成员scrollTop仍1474，第17条y仍269.625；出现“1条未读 · 看最新消息”。约7秒观察窗口内没有chat:read，消息168在DOM中但不在阅读区域，不被提前读掉。 |
| 点击最新消息 | 实际点击未读入口后发送chat:read seq=168，未读消除，滚动到底部。DOM序号1–168严格递增、168个唯一项、无缺号。这里序号连续是隔离库的结果，不要求真实多房间全局序号连续。 |

## 失焦与恢复焦点

内置浏览器默认焦点模拟使两个标签都报告hasFocus=true，不能据此把工具切换当成后台。开发测试临时关闭成员标签的Emulation.setFocusEmulationEnabled，通过原生document.hasFocus读取验证实际失焦；没有改写DOM的可见性属性或应用状态。

实际点击房主输入框并发送消息167后，成员document.visibilityState=visible、hasFocus=false。约7.531秒后消息167已显示，仍有1条未读，观察窗口内无chat:read。截图chat-unfocused-unread-20261009.jpg保存时再次读取仍是失焦。实际点击回成员聊天输入框后，hasFocus=true，发送chat:read seq=167，未读消除。测试后焦点模拟恢复原设置。

这证明“可见但失焦”时不读，以及实际返回焦点后才读；没有证明visibilityState=hidden、系统冻结/杀进程或真机后台场景。相关条件已有组件回归，真实隐藏/挂起仍留待后续。

## 浏览器异常与边界

生成40条后发现旧成员标签10已显示浏览器崩溃页；尝试焦点测试命令时被当前崩溃页的URL规则阻止，不能声称该命令已执行，也没有绕过崩溃页限制。房主页面及聊天服务仍响应；在同一内置浏览器新建成员标签15继续，未重启服务。崩溃原因未确认，本报告不归因于产品或宣布修复。

原始结果见chat-pagination-browser-20261009.json。分页请求/回复与两次已读窗口均hasMore=false、truncated=false。截图：chat-history-reading-20261009.jpg、chat-history-new-unread-20261009.jpg、chat-latest-read-20261009.jpg。截图中的彩条/片尾为本地测试影片，不是真实上游影视源。
