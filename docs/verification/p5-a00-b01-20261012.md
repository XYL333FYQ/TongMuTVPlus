## 脚本实际判断错误与修订

1. 按整个 className 合并推断主操作，漏掉从字面量开头开始的彩色选中分支；会把选中态也改成中性背景。新增失败回归后改为逐分支推断，选中为 --tm-text/--tm-accent-contrast，未选为中性背景/--tm-text，条件保留。
2. 白色滑块直接套普通 surface，会与关闭轨道同色。手工用现有 aria-checked 的 CSS 选择器反色；没有新增状态、handler 或条件逻辑。最终两主题均验证开/关对比。
3. 浅色 bg-amber-50 与 dark:bg-amber-500/10 被当作两个独立角色，深色背景误变 --tm-text，产生白底白字；check-design 为 0 仍不能发现对比度错误。已补失败回归，并按整组低强调背景配对映射 raised；保留错误诊断图。
4. 页面渐变最初一律替 surface；已按页面背景角色使用 --tm-bg，移除 warning 根渐变与 from/to 类。最终警告文字、图标、面板层次可读；保留两个原 emoji 为明确 TODO，未改 JSX 文案。
5. 自动换 TV 外层会叠加 TVLayout 的 32px 内边距；手工只调整 PageContainer 的宽度/居中公式，1440 上限保持，未动内部两列。其浅色标题原本继承白字，也补了 --tm-text。
6. 自动补 tm-press 只覆盖按钮本身，旧滑块 transition-transform 仍不响应减少动态；在同一滑块样式中补系统及 html 偏好选择器。正常 transition-property=transform，系统 reduce 或用户开关开启时 property=none。duration 仍可能显示 150ms，但 property=none 表示不会执行过渡，不能仅用 duration 数字判断。

脚本另外补加载转圈 TODO 和裸 main 下外层容器识别；两页试运行八项回归继续通过。它仍须逐批审 diff 和真实浏览器验收，不能靠扫描计数自动宣布全站通过。
