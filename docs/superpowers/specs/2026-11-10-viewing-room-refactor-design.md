# 一起看：以 SyncTV 为基础的模块接入方案

日期：2026-11-10。状态：调研和隔离验证，未实施到产品。源码基线 `0907bbb0a577c01bbace346215abfb01bef5cde4`。

## 1. 方向与边界

用户明确：**以 SyncTV 的实现和行为为准，把 SyncTV 的功能作为本站的“一起看”模块接入；现有房间模块按半废弃实现处理。**之前“优先复用旧房间服务、稍后才决定是否换成 SyncTV”的建议作废。

采用 SyncTV 的房间能力和服务端作为基底，房间、同步、成员、权限、片单、聊天等功能和行为以 SyncTV 为基准；界面按本站总体风格实现。本站承担入口、账号、片源、播放和界面衔接，不重新造一套房间状态机。自己看与一起看是各自职责清晰又可协作的平级模块，既可以分别使用，也要能互相带入内容和衔接播放。

SyncTV 不是可直接 import 的 React 组件：服务端为独立 Rust 程序，本次测试使用 PostgreSQL；其官方客户端为 Flutter，包含 Web 构建。官方 Web 界面用于验证和参考功能，不能直接作为本站最终界面。需评估复用其播放及协议能力的方法，并以本站组件和设计规范实现相应交互；具体边界以原型验证为准。全屏、画中画、通知、登录、手机手势、返回行为及播放器状态衔接均须验证。

旧房间 Socket.IO 服务、旧房间页面及其与播放器的同步桥只作为现状和迁移资料；在新模块通过验收、旧数据及兼容问题有处理方案后清理。不能未经确认清空用户房间或聊天历史，也不以保留旧服务的行为限制 SyncTV 的正常功能。

本任务超出现行换皮禁区，未来实施可能涉及 `server/`、房间 hooks、播放会话、API、数据与部署依赖；本文件只提出可审阅的方向，不能当作已经修改或部署的证明。现有个人播放能力及已有用户数据应受到保护。

## 2. 已明确的体验

- 新房间模块显示在现有桌面主导航“发现、片库、房间”中的“房间”界面，保留 `/watch-room` 入口，并接通首页已有的房间摘要与入口；手机等其他入口也应保持可达。
- 模块结构高内聚、低耦合：房间状态、同步、成员、消息等归房间模块负责；账号、片源和播放等共享能力通过明确接口协作，不通过两个模块相互直接依赖内部实现来串联功能。
- 房间的页面、组件和交互遵循本站现有总体风格及 `docs/design/DESIGN.md`，不直接沿用 SyncTV 的原生界面。以 SyncTV 为功能和行为基准，逐项落实到本站界面，而不是只接入少数基础功能。
- 自己看与一起看为平级功能；选片或正在自己看时可以创建房间，带入正确影片和集数；也可直接从房间入口创建或加入。
- 两个模块共享合适的影片、剧集、片源等能力，并支持从自己看发起一起看；在房间内也可使用本站的选片能力。房间与个人播放的具体切换、状态保持和声音协调须验证，不能把各自独立误解成互相隔绝。
- 一起看优先保留 SyncTV 现有的房间设置、成员管理、邀请、聊天、弹幕、片单和播放能力。逐项核对本站用户需要的播放能力，缺口单独记录，不能因为使用了 SyncTV 就视为全部相同。
- 房间封面由房主上传本地图片；未设置自定义封面时使用正在播放影片的海报；都不可用时使用占位。SyncTV App v1.1.32 的设置页已有本地选图、更新和移除房间封面的源码，其上传服务有文件大小和图片类型限制；**未在本站浏览器实测**。该版本的房间卡片在传入的 `coverUrl` 为空时使用占位；是否由服务端填入当前影片海报尚未证明，需要验证并补齐用户要求。
- 封面回退是展示时的选择：自定义图片始终优先，换片不能覆盖用户上传的图片；移除自定义图片后才显示当前影片海报，不能把自动海报写成永久自定义封面。
- 除用户明确提出的本站需求外，房间权限、播放控制等行为遵循所选 SyncTV 版本及实际配置，不把旧房间的单设备控制或旧事件格式当作必须保留的规则。不同设备、弱网和断线后的表现要实测。

## 3. 已验证什么

隔离运行官方 SyncTV 服务端 v1.0.14 和 PostgreSQL 18，在临时数据库中使用两个测试账号和项目现成的 13,083 字节 MP4 夹具。无需真实用户账号，也未把实验服务接入项目。

- 两个账号创建/加入同一房间，建立独立 WebSocket；测试片源可加入并启动共享播放状态，两个连接收到相同影片与 12 秒跳转事件；成员重连后收到最新状态。
- 默认配置下普通成员跳转被拒绝；聊天事件到达第二个连接。相同账号的两个连接在实验中均可控制其房间，包括普通账号创建的房间；这是此次观测，不推断所有设备和配置都相同。
- 两个服务重启后，测试账号重新登录，房间、两个成员、媒体条目和聊天记录仍存在；**未验证精确播放时间、生产备份或旧数据迁移**。
- 旧站 Socket.IO 握手对 SyncTV 返回 404；本站旧格式的测试片源引用直接提交被拒绝。必须对接 SyncTV 的接口和片源格式，不能只改服务地址。显式使用 protobuf WebSocket 格式的心跳已得到回应；此版默认格式并非一定是 protobuf。
- 官方 Web 首页及启动脚本 HTTP 200；真实 Chrome 已打开房间目录并看到两个测试房间，未在浏览器完成登录及视频播放。

原始测试和镜像来源、详细限制见 [隔离验证记录](../../design/SYNCTV-VALIDATION-20261110.md)。这里验证的是服务和协议状态，**不是两个真实浏览器的视频播放验收**。

## 4. 接入方案与待验证的连接点

### 4.1 部署与客户端

固定匹配的 SyncTV 服务端/客户端版本，在独立环境验证上游功能作为对照。最终房间界面接入本站现有 `/watch-room` 页面与导航，遵循本站设计，不直接嵌入原版 SyncTV 页面。评估如何复用或适配上游播放和协议能力，使本站前端与 SyncTV 服务协作；确定 API/WebSocket 路由、认证、会话和播放器生命周期边界，并验证全屏、画中画、音频焦点和客户端兼容性。

SyncTV 需要自己的运行时、PostgreSQL、配置、文件存储和备份；这些是增加的部署与维护成本。是否需要 Redis、何种图片存储及反向代理，应以实际选用配置和上游要求为准，不假定现有 SQLite 可以直接替代。开源代码和构建产物须保留对应许可及第三方声明。

### 4.2 账号

本站已有登录和用户状态；SyncTV 有独立用户、会话及权限，两者的 Cookie 和身份不能直接互认。本站现有 OIDC 代码证明它可作为第三方登录的客户端，不能据此认定它已经是可供 SyncTV 使用的身份提供方。

目标是让用户使用本站身份进入 SyncTV，并保持每个人独立身份及权限。使用稳定的本站用户 ID 绑定，不能仅凭昵称或邮箱自动合并。先做隔离原型，比较已有可用的统一身份提供方与安全的服务端身份桥，验证账号绑定、首次创建、退出、禁用和会话撤销；不要为所有人共用管理员令牌，也不要把长期令牌放在 URL。具体方案以原型与安全边界为准，当前尚未证明无感登录可用。

### 4.3 本站选片

从本站选片、集数、海报及必要播放信息构造 SyncTV 能接受的媒体，使用 SyncTV 自有媒体列表与同步。实验已证明本地 MP4 直链可以作为测试媒体提交，**不证明本站真实来源全部兼容**。须分别验证真实 MP4/HLS、不同成员的访问权限、跨域、Range、过期链接、来源请求头和字幕；不得将本站密钥或其他用户不可见的凭据交给房间成员。片源不能直接使用时研究受权限限制的代理或 SyncTV provider，不能为了兼容而重写 SyncTV 同步。

### 4.4 封面

优先沿用上游已有的上传和删除流程。对用户要求的海报回退，先核对房间发现接口及当前播放信息能否安全取得影片海报；需要补充时仅增加必要的映射或展示逻辑。验证公开和私密房间的访问控制、切片后的刷新、上传覆盖及删除、图片失效、备份恢复；不能让私密内容在公共房间卡片泄露。

### 4.5 旧模块与数据

盘点旧房间、成员、片单、消息、邀请、音乐/直播/屏幕共享和用户依赖。旧 SQLite 数据与 SyncTV PostgreSQL 模型不同，不假定可直接导入或完整对等；先用数据副本验证映射和回滚，再明确无法迁移的项目及旧邀请如何处理。切换前保留可恢复备份；切换和清理旧实现应在功能及迁移验收之后执行，具体数据取舍由实际迁移结果决定。

## 6. 验收重点

1. 两个独立浏览器账号进入正式接入的房间，实际播放并可观察声音和画面，验证播放、暂停、跳转、换片、聊天、掉线重连和权限；再覆盖不同网络及手机/桌面客户端。
2. 在本站自己看选择某影片某集，带入房间且另一位用户能播放；验证真实来源的 MP4/HLS、字幕及过期/跨域处理。
3. 现有导航中的“房间”入口与首页房间摘要都能进入新模块；房间 UI 与本站整体风格一致，房间内可选本站影片，两个模块协作时不相互侵入内部实现。
4. 在房间设置中上传和移除本地封面；清除后显示当前影片海报，再无海报时显示占位；检查公开/私密权限与切片更新。
5. 验证本站登录、退出、账号禁用及对应 SyncTV 身份和权限；验证页面切换、后台音频、全屏、小窗、客户端返回及旧 Android/WebView 的实际兼容性。
6. 用旧数据副本执行迁移、校验和恢复演练，记录不可迁移项目；在新链路经确认后移除旧依赖。
7. 运行项目规定的 `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm format:check`、`pnpm test:rooms`，并在 390、820、1280 宽各验证深浅主题截图。自动测试通过不能代替实际浏览器与真实来源验证。
