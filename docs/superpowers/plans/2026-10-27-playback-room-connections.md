# 播放与房间连接实施计划

> 执行技能：executing-plans；每批按 TDD 实现。用户已明确授权「按计划进行」。不提交、推送或部署。

**Goal:** 消除播放意图、房间快照与异步操作争写；统一所有选片入口，接通待看、双向房间实时弹幕和附属活动。

**Architecture:** 页面位置、成员关系、观看模式、当前设备控制权、画面形态分别管理。每项操作绑定房间、媒体与代次；快照只在跟随模式应用媒体，不导航。聊天是唯一持久消息源，画面实时消息是展示消费者。

**Tech Stack:** Next.js14、React18、TypeScript、Socket.IO、SQLite，沿用已有依赖。

**Spec:** 用户确认的线路图/动作表；详细审计位于 output/playback-room-connection-audit-20261026/REPORT.md（第 1–13 节）。本计划与 DESIGN.md 新条目为长期实现依据。

## Global Constraints

- 用户授权本轮必要修改 PlaybackSessionProvider、usePlaySync、useWatchRoom、LegacyPlaybackSurface 行为和房间服务；其他禁区保持。不做无关重构，不新增依赖，不删除路由，不改 Socket 事件名和数据库路径。
- 普通导航不改变观看模式。普通播放明确自己看，房间选片使用共同观看意图。片单先追加、主持确认播放，不擅自自动续播下一部电影。
- 新房间消息只实时飘过一次；历史补齐不飘屏，外部历史弹幕不写入聊天。保持已读可见性规则。
- 相同电影完整/小窗/折叠保留实例；只有明确换媒体或重试可重建媒体。
- 现有工作区建立 codex 分支，沿用依赖与预览位置，不额外创建 checkout。不提交、不推送、不部署。
- 每批先跑失败回归，再实现，最后定向和项目要求的检查；Windows 原生崩溃按 AGENTS 处理并保留日志。预览与检查串行。

## Review Focus

1. 新选片与旧房首次/重连快照先后顺序不同，结果仍尊重个人意图。
2. 切房、切活动、连续选择后的旧 ACK/查源/采集结果不影响当前媒体或页面。
3. 房主身份、当前设备控制权与 following 不能互相替代。
4. 快照回声不生成新命令；所有媒体共享声音归属。
5. 双向消息同源、去重、可失败重试，历史不轰炸画面，全屏输入可达。
